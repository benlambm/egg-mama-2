# Egg Mama

A landscape-oriented platformer PWA for phones: roll Mama the egg home across
thirteen chapters, gather the scattered clutch, and hatch the golden eggs into
duckling extra lives. Full-screen playfield, no HUD chrome — swipes steer, the
page never scrolls, and the horizon stays steady through jumps.

The game has **no dependencies and no build step** — plain HTML/CSS/JS with a
service worker for offline play.

## Run it

```sh
cd egg-mama-2
python3 -m http.server 8080     # or: npm run serve
```

Open `http://localhost:8080` on a phone (or in a landscape browser window) and
"Add to Home Screen" for the fullscreen PWA experience. Serve over HTTP(S) —
service workers and the manifest require it; `file://` will not register the SW.

## Controls

| Input | Action |
|---|---|
| Swipe up / `↑` / `W` / `Space` | Jump |
| Swipe left / `←` / `A` | Brake / roll back |
| Swipe right / `→` / `D` | Boost (speed burst) |
| `P` | Pause |
| `M` | Mute all audio |
| Tap pause button (top-right) | Pause |

Turning the phone to portrait pauses the run and asks you to turn sideways;
tap to resume once landscape is restored.

## The game

- **Goal:** reach the beacon at the end of each of the 13 chapters
  (Meadow → Clover Mill → Reedwater → Orchard Heights → Amber Quarry → Fogwood →
  Ember Canyon → Glass Coast → Lantern Caverns → Frostline → Moonridge →
  Dawnbridge → Beacon Summit).
- **Eggs** are points and route markers. **Golden eggs** hatch into ducklings —
  up to 5 follow Mama as extra lives.
- **Damage is shield-first:** a hit pops the shield, then costs a duckling, then
  ends the run. Falling into a pit respawns you at the last checkpoint.
- **Checkpoints** (flags) autosave; Continue on the title screen resumes there.
  After the summit you can keep rolling an endless circuit of the final chapter.
- Progress, settings, and the trail journal persist in `localStorage`
  (`egg-mama-2.save.v2` / `egg-mama-2.settings.v1`) and sync live across two
  open tabs. Best-effort migration from the original game's save keys is
  included (see "Assumptions" below).

## Tests

```sh
npm test        # node --test tests/*.test.js  → 23 tests
```

- `tests/engine.test.js` — physics (jump arc, coyote, buffer, step-up), lifts,
  crumble, magnet, shield-first damage, fall→checkpoint, serialize round-trip.
- `tests/progress.test.js` — save record/migrate/sync/parse tolerance.
- `tests/reach.test.js` — BFS jump-reachability proof: every chapter × 6 seeds is
  completable, and checkpoint positions sit on solid ground (78/78).
- `tests/shell.test.js` — service-worker FILE list matches disk, manifest,
  index references, view jump-fit, background files present.
- `tests/helpers.js` — a seeded analytic bot (solves the exact jump arc) used to
  play chapters headlessly in Node.


## Tuning

All feel constants live in `js/tuning.js` (`EM.TUNING`): cruise/boost/brake
speeds, gravity, jump speed, coyote time, input buffer, step-up height, max
flock, lift angular speed, enemy speed, camera fit, parallax factor, and more.
Chapter difficulty (piece weights, section time bands, palettes, music) lives in
`js/levels.js`. After changing any file, bump `VERSION` in `sw.js` (see below).

## Service worker / cache versioning

`sw.js` caches an explicit `FILES` list, cache-first, under the prefix
`egg-mama-2-`. **Whenever any listed file changes, bump `VERSION`**
(e.g. `egg-mama-2-valley-1` → `egg-mama-2-valley-2`): the SW installs the new
cache, activates, deletes old `egg-mama-2-*` caches, and takes control
immediately, so returning players get the new build even offline.
`tests/shell.test.js` enforces that `FILES` matches the files on disk.

## Architecture notes

- **Fixed-step simulation.** `engine.update(dtMs)` advances in 8.333 ms steps, so
  gameplay is identical at 60 fps and 120 fps; rendering interpolates nothing and
  just draws the latest state.
- **Engine is DOM-free** (importable in Node) — that is what makes the headless
  tests and the reachability proof possible. Rendering, audio, input, and storage
  are separate modules wired together in `main.js`.
- **Seeded levels.** Each chapter is generated from `(chapterIndex, circuit,
  seed)`; a chapter replayed with the same seed is identical, which is what the
  tests rely on. Checkpoints are guaranteed before hard pieces and roughly every
  16–26 s, and at least two golden eggs are always placed.
- **Audio is synthesized** at runtime with Web Audio (no audio files): SFX are
  short enveloped osc/noise bursts, and each chapter's music is an 8-bar loop
  built from a shared Meadow motif transposed per chapter, with per-chapter tempo,
  root, mode, intensity, and lead/stab waveforms. Golden hatches and checkpoints
  are deliberately loud so they cut through phone speakers.
- **Art direction follows Egg Runner 2:** warm upper-left light, color families
  per chapter palette, outlines in each shape's own color, sprite caches and
  mip-stamped ground, and soft contact shadows under Mama, ducklings, and eggs.
- **Backdrops** are the 13 original paintings, drawn cover-fit and wrapped with
  alternate tiles mirrored so the wrap seams read as reflections, not cuts.
- **DPR/quality caps** (`MAX_PIXELS`, `MAX_DETAIL` in tuning) keep fill-rate sane
  on phones; `prefers-reduced-motion` trims particles and shake.

## Assumptions

- The original `egg-mama` repo was used **only** for its 13 background images;
  its code was not consulted. Its legacy save keys
  (`egg-mama.save.v1`, `egg-mama-save`, `eggMamaSave`) are therefore guesses —
  `progress.js` tries each best-effort and maps ducklings/checkpoint progress if
  found. If a real legacy key is known, add it to `LEGACY_KEYS`.
- Chapter names beyond Meadow were invented to fit the 13 backdrops in order.
- Physical-device acceptance (scroll lock, rotation, jump readability, sound on
  phone speakers) was verified in headless Chromium; a real-device pass on iOS
  Safari and Android Chrome is still worth doing before shipping.
